## 1. Purpose

## 3. Stages of Delivery

### Stage 1: Sprint & Technical Execution
- **Architecture & Setup:** Project repository setup under B2C Solution GitHub organization with branch protection rules.
- **Development:** Code developed according to agreed specifications, modular architecture, and security guidelines (`security/SECURITY_POLICY.md`).
- **Third-Party Dependency Tracking:** Open-source software and third-party libraries tracked in accordance with `legal/THIRD_PARTY_LICENSES.md`.

### Stage 2: Staging, Testing & Quality Assurance
- **Internal QA:** Testing performed for functional correctness, responsiveness, performance, and security vulnerabilities.
- **Staging Deployment:** Project deployed to a secure staging environment for demonstration and integration testing.

### Stage 3: Client Review & Milestone Demonstration
- **Staging Access:** Client is provided access to review deliverables against agreed criteria (`business/QUOTATION_TEMPLATE.md`).
- **Feedback Consolidation:** Client provides consolidated feedback. Minor bug fixes within scope are addressed; out-of-scope requests trigger a formal Change Order.

### Stage 4: Acceptance & Final Sign-Off
- **Milestone Acceptance:** Client confirms acceptance of the deliverable upon satisfactory review.
- **Final Invoicing:** Final invoice issued in accordance with `business/INVOICE_TERMS.md`.

### Stage 5: Production Deployment & Transfer
- **Final Payment Verification:** Production deployment proceeds upon settlement of outstanding invoices.
- **Production Launch:** Deployment to client's live hosting environment or domain.
- **Deliverable Transfer:** Transfer of production credentials, documentation, or repositories as per `legal/CLIENT_SERVICE_AGREEMENT.md`.

### Stage 6: Post-Launch Warranty & Support
- **30-Day Warranty:** 30-day warranty period for bug fixes within the original project scope.
- **Ongoing Maintenance:** Continued support or maintenance governed by separate service arrangements.

---

## 4. Change Control Management

Any request to modify project scope, feature specifications, or deliverables must follow a structured change process:

1. **Change Request:** Client submits written details of the requested modification.
2. **Impact Assessment:** B2C Solution evaluates impact on timeline, complexity, and cost.
3. **Change Order Approval:** B2C Solution provides a Change Order quote. Work on the modification begins after written Client approval.
